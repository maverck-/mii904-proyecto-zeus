# 5. Priorización

Estado: criterio y orden inicial para revisar. Fuente: enunciado, p. 8. El orden se aplica a capacidades del backlog, no a la lista de alternativas del Business Case.

## Método

Primero verificar restricciones de presupuesto, continuidad, ERP/WMS y controles. Después comparar valor, urgencia, dependencia, riesgo, incertidumbre, costo y capacidad. Un puntaje puede ayudar a discutir, pero no elimina interdependencias ni sustituye decisiones.

| Criterio | Pregunta |
| --- | --- |
| Valor | ¿Qué beneficio medible habilita y para quién? |
| Urgencia | ¿Afecta primer valor M5 o preparación M8? |
| Dependencia | ¿Qué habilita y qué necesita antes? |
| Riesgo | ¿Qué exposición reduce o añade? |
| Incertidumbre | ¿Qué aprendizaje conviene obtener temprano? |
| Costo | ¿Cuál es su rango y costo de oportunidad? |
| Capacidad | ¿Qué equipo o proveedor limita el avance? |

## Orden de trabajo propuesto

1. CAP-01 con CAP-05/CAP-06 desde inicio: comprobar integración, base, controles y capacidad.
2. CAP-02/CAP-03: disponibilidad y pedido confiables.
3. CAP-04: flujo usable C&C con beneficio medido dentro de M5.
4. CAP-07: estabilizar y escalar cobertura aceptada para evento M8.
5. CAP-08: devolución elegible cuando estados, reglas y capacidad lo permitan.

Si una validación indica que otra capacidad produce más valor o es una dependencia real, actualizar el orden y sus efectos. Priorizar habilitadores se justifica por este flujo; no es una regla universal de favorecer tecnología frente a negocio.

## Completar

Contrastar costos/capacidad, acordar releases e inclusiones y registrar trade-offs. Si se usa scoring, definir escala y pesos con fundamento y conservar la explicación de secuencia. CAP-05/CAP-06 no pueden descartarse por tener menor puntaje comercial. Las restricciones del caso siguen vigentes.
